# Daily Sales Forecasting

## Day 4 – Forecasting Prototype

### Objective

Develop a baseline machine learning model to forecast daily sales using historical transaction data.

### Dataset

Input: `daily_sales.csv`

Columns used:

- Order Date
- Total amount

### Data Preparation

The following preprocessing steps were performed before model training:

- Converted `Order Date` to datetime format.
- Sorted records by date.
- Generated time-based features:
  - Day
  - Month
  - Year
  - Day of Week
  - Week of Year
  - Quarter
- Generated lag features:
  - Lag 1
  - Lag 7
  - Lag 30
- Generated rolling statistics:
  - Rolling Mean (7 days)
  - Rolling Mean (30 days)
- Removed rows containing missing values generated due to lag and rolling calculations.

### Model

Algorithm:

- LightGBM Regressor

Model Parameters

- Random State: 42
- Number of Estimators: 200
- Learning Rate: 0.05

### Training

The dataset was split chronologically:

- Training Data: First 80%
- Testing Data: Remaining 20%

The model was trained using the generated features to predict daily sales.

### Output

The trained model was saved as:

```
lightgbm_daily_model.pkl
```

### Visualizations

The following plots were generated:

- Actual vs Predicted Daily Sales
- Prediction Error (Actual − Predicted)
- Feature Importance

---

## Day 5 – Model Evaluation

### Evaluation Metrics

The trained model was evaluated using:

- Mean Absolute Error (MAE)
- Root Mean Squared Error (RMSE)

### Performance Analysis

The comparison between actual and predicted values indicates that the model successfully captures the overall sales trend while maintaining acceptable prediction accuracy.

Feature importance analysis shows that historical sales values (lag and rolling features) contribute significantly more than calendar-based features.

### Limitations

- Predictions depend heavily on historical sales.
- Sudden spikes caused by promotions or special events may not be captured accurately.
- External business factors are not included.

# Weekly Sales Forecasting

## Day 4 – Forecasting Prototype

### Objective

Develop a baseline forecasting model to predict weekly sales using aggregated historical sales data.

### Dataset

Input: `weekly_sales.csv`

Columns used:

- Week
- Total amount

### Data Preparation

The weekly dataset was generated by aggregating daily sales records.

The following features were created:

Time Features

- Week Number
- Month
- Quarter
- Year

Lag Features

- Lag 1 Week
- Lag 2 Weeks
- Lag 4 Weeks

Rolling Features

- Rolling Mean (4 Weeks)
- Rolling Mean (8 Weeks)

Rows containing missing values after feature creation were removed.

### Model

Algorithm:

- LightGBM Regressor

Model Parameters

- Random State: 42
- Number of Estimators: 200
- Learning Rate: 0.05

### Training

Chronological train-test split:

- Training Data: First 80%
- Testing Data: Remaining 20%

The model was trained to predict weekly sales.

### Output

The trained model was saved as:

```
lightgbm_weekly_model.pkl
```

### Visualizations

The following graphs were generated:

- Actual vs Predicted Weekly Sales
- Prediction Error (Actual − Predicted)
- Feature Importance

---

## Day 5 – Model Evaluation

### Evaluation Metrics

Model performance was evaluated using:

- Mean Absolute Error (MAE)
- Root Mean Squared Error (RMSE)

### Performance Analysis

The weekly forecasting model effectively follows long-term sales trends and provides smoother predictions compared to the daily model because weekly aggregation reduces daily fluctuations.

Lag features and rolling averages contributed most to prediction accuracy.

### Limitations

- Weekly aggregation removes daily-level variations.
- Model accuracy decreases when unexpected market changes occur.
- Forecast quality depends on the availability of sufficient historical data.
