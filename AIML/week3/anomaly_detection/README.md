# Day 8 – Anomaly Detection Refinement

## Overview

Day 8 focuses on improving the anomaly detection module developed in the previous milestone.

The Week 2 implementation detected anomalies using the **Mean ± 2 × Standard Deviation** statistical rule. Although effective, this approach can generate unnecessary anomaly alerts because the mean and standard deviation are influenced by extreme values.

In Week 3, the anomaly detection rule was refined by replacing the previous approach with an **Interquartile Range (IQR)** based method using a **3 × IQR threshold**. This refinement produces a stricter anomaly detection rule and reduces unnecessary anomaly alerts.

---

# Objective

The objectives of Day 8 are:

- Refine the existing anomaly detection rule.
- Reduce false-positive anomaly alerts.
- Re-test the refined rule on the same transaction dataset.
- Compare Week 2 and Week 3 anomaly detection approaches.
- Integrate the updated anomaly results with the Flask API.

# Methodology

## 1. Daily Sales Aggregation

Individual transactions were grouped using **Order Date**.

The total sales for each day were calculated.

Example:

| Order Date | Total Sales |
|------------|------------:|
| 2011-01-01 | 3,250 |
| 2011-01-02 | 4,180 |
| 2011-01-03 | 2,940 |

The anomaly detection process was performed on these daily sales values.

---

## 2. Quartile Calculation

The daily sales values were sorted in ascending order.

The following statistical measures were calculated:

- First Quartile (Q1)
- Third Quartile (Q3)

These quartiles represent the spread of the middle 50% of the data.

---

## 3. Interquartile Range (IQR)

The Interquartile Range was calculated as:

```
IQR = Q3 − Q1
```

The IQR measures the spread of the central portion of the dataset and is less affected by extreme values than the mean and standard deviation.

---

## 4. Anomaly Threshold Calculation

The anomaly limits were calculated using the refined statistical rule:

```
Lower Limit = Q1 − (3 × IQR)

Upper Limit = Q3 + (3 × IQR)
```

Any daily sales value outside these limits was classified as an anomaly.

---

## 5. Anomaly Detection

Each day's total sales was compared against the calculated limits.

If:

```
Total Sales < Lower Limit
```

or

```
Total Sales > Upper Limit
```

the record was labelled as:

```
Anomaly = True
```

Otherwise:

```
Anomaly = False
```

# Results

## Comparison

| Metric | Week 2 | Week 3 |
|--------|--------:|--------:|

The refined IQR-based rule reduced the number of detected anomalies from **59** to **22**, resulting in fewer anomaly alerts while identifying only the most significant outliers.
